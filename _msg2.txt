Phase 1 continued: SPA shells, outlet scoping, CI

Frontend
- Two Vue entry points mirroring the ordering system: the public punch PWA and the
  gated console. Vite builds both; verified they compile and the shells serve.
- The punch app is a PWA (manifest, apple-touch-icon) because it is the only
  surface staff use, and installing to the home screen saves them finding a
  bookmark every shift. No webfont: the punch screen is used one-handed in a
  kitchen on whatever connection exists.
- The console deliberately gets NO service worker, matching the ordering system's
  reasoning — a cached timesheet would show a manager hours that are no longer true.
- No router in the punch app: the flow is short and linear (scan, PIN, photo,
  status), so URL states would need guarding without helping.

Security plumbing
- ForceJsonResponse, prepended to the API group. Without it an unauthenticated
  request that does not send Accept: application/json is redirected to a `login`
  route that an API-only app does not have, surfacing as an HTTP 500 instead of a
  401. That misdiagnosis cost real time on the ordering system.
- ScopesToOutlets with visibleTo()/isVisibleTo(). This is a security boundary, not
  a convenience filter: a manager at Sg Ramal must not reach Sedap Santai's staff,
  hours or photos even by crafting a request. An owner resolves to "no
  restriction"; a manager with no mappings resolves to "restriction to nothing",
  so forgetting to grant access FAILS CLOSED rather than exposing everything.
- User::visibleOutletIds() returns NULL for an owner meaning "all outlets", kept
  distinct from an empty array meaning "none" so a careless in_array cannot read
  no-access as full access.

Removed scaffold leftovers that no longer reflect this app: the default
welcome view, app.js, and the two ExampleTest placeholders (one of which failed
by asserting the root returns 200, when it now redirects to /punch by design).

CI
- Tests and style on every push.
- A second job migrates against a real MySQL 8.4 service and asserts the
  one-open-segment index exists and is unique. SQLite and MySQL implement that
  invariant with different SQL, so running only SQLite in CI would leave the
  production mechanism unverified.

Tests: RoutingSmokeTest (7) covering the traps — the punch catch-all must not
swallow /console or the API, an unauthenticated API call must be 401 not 500, and
the console must not cache. 15 passing, Pint clean.
